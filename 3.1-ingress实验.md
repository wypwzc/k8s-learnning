# Kubernetes Ingress 实战实验（超经典）

这个实验会让你真正理解：

```
用户浏览器
    ↓
Ingress
    ↓
Service
    ↓
Pod
```

也是你第一次接触：

- 七层代理
- 域名转发
- HTTP 路由
- Nginx Ingress Controller
- K8s 南北流量入口

这是 K8s 网络体系最关键的一步之一。

------

# 一、实验目标

实现：

```
http://nginx.local  → nginx服务
http://tomcat.local → tomcat服务
```

最终效果：

不同域名 → Ingress → 不同 Service → 不同 Pod

这就是：

```
Ingress = K8s里的 Nginx 反向代理
```

------

# 二、实验架构图

```
                用户浏览器
                     |
         -------------------------
         |                       |
   nginx.local             tomcat.local
         |                       |
         -------- Ingress -------
                     |
          -------------------
          |                 |
    nginx-service     tomcat-service
          |                 |
       nginx pod        tomcat pod
```

# 六、查看是否安装成功

```
kubectl get pods -n ingress-nginx
```

看到：

```
ingress-nginx-controller Running
```

即可。

再看：

```
kubectl get svc -n ingress-nginx
```



注：这个地方看svc的时候会pending

原因从官网下载的是云厂商的 LoadBalancer，要把它改成 **`NodePort`** 

直接运行以下命令编辑正在运行的 Service：

```
kubectl edit svc ingress-nginx-controller -n ingress-nginx
```

这会打开一个 Vim 编辑器，找到以下内容并修改：

1. 找到 `type: LoadBalancer`，将其修改为：

   ```
   type: NodePort
   ```

你会看到：

```
TYPE: NodePort
```



比如：

```
80:30539/TCP
443:32404/TCP
```

记住这个端口。

# 七、部署 nginx

## nginx-deploy.yaml

```yaml
apiVersion: apps/v1
kind: Deployment

metadata:
  name: nginx

spec:
  replicas: 1

  selector:
    matchLabels:
      app: nginx

  template:
    metadata:
      labels:
        app: nginx

    spec:
      containers:
      - name: nginx
        image: nginx:1.25

        ports:
        - containerPort: 80
```

部署：

```
kubectl apply -f nginx-deploy.yaml

# 十一、创建 Ingress

## ingress.yaml

```
apiVersion: networking.k8s.io/v1
kind: Ingress

metadata:
  name: demo-ingress

spec:
  ingressClassName: nginx

  rules:

  - host: nginx.local

    http:
      paths:
      - path: /
        pathType: Prefix

        backend:
          service:
            name: nginx-service

            port:
              number: 80

  - host: tomcat.local

    http:
      paths:
      - path: /
        pathType: Prefix

        backend:
          service:
            name: tomcat-service

            port:
              number: 8080
```

部署：

```
kubectl apply -f ingress.yaml
```

# 十五、真正理解 Ingress

现在你要彻底理解：

------

## 1. Service 是四层转发

Service 不看：

```
域名
URL
HTTP Header
```

只看：

```
IP + PORT
```

这是：

```
L4
```

------

## 2. Ingress 是七层代理

Ingress 可以看：

```
Host
Path
Cookie
Header
```

所以它能：

```
nginx.local -> nginx
tomcat.local -> tomcat
/api -> backend
/static -> frontend
```

这叫：

```
HTTP 路由
```

```

然后：

```
按域名/路径分发。
```

# 三、修改 ingress.yaml

## ingress-path.yaml

```
apiVersion: networking.k8s.io/v1
kind: Ingress

metadata:
  name: path-ingress

spec:
  ingressClassName: nginx

  rules:
  - host: demo.local

    http:
      paths:

      - path: /nginx
        pathType: Prefix

        backend:
          service:
            name: nginx-service

            port:
              number: 80

      - path: /tomcat
        pathType: Prefix

        backend:
          service:
            name: tomcat-service

            port:
              number: 8080
```

部署：

```
kubectl apply -f ingress-path.yaml
```

# 六、这里会出现一个经典问题（重点）

# 七、为什么会 404？

Ingress 只是：

```
转发请求
```

它不会自动：

```
删除路径前缀
```

所以：

```
/nginx
```

被原样转发给 nginx。

而 nginx 只有：

```
/
```

没有：

```
/nginx
```

# 八、rewrite（企业必学）

所以企业一定会用：

```

```

```

```

```

# 九、rewrite 实战

## ingress-rewrite.yaml

```
apiVersion: networking.k8s.io/v1
kind: Ingress

metadata:
  name: rewrite-ingress

  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /

spec:
  ingressClassName: nginx

  rules:
  - host: demo.local

    http:
      paths:

      - path: /nginx
        pathType: Prefix

        backend:
          service:
            name: nginx-service

            port:
              number: 80
```

```

# 十二、HTTPS 原理

本质：

```
Ingress termination TLS
```

即：

```
浏览器 <-> Ingress
HTTPS

Ingress <-> Pod
HTTP
```

Ingress 负责：

- TLS 握手
- 证书

------

# 十三、生成 TLS Secret

先生成证书。

------

## 创建自签名证书

Linux：

```
openssl req -x509 -nodes -days 365 \
-newkey rsa:2048 \
-keyout tls.key \
-out tls.crt
```

一路回车。

------

# 十四、创建 Secret

```
kubectl create secret tls demo-tls \
--key tls.key \
--cert tls.crt
```

查看：

```
kubectl get secret
```

# 十五、Ingress HTTPS 配置

## ingress-https.yaml

```
apiVersion: networking.k8s.io/v1
kind: Ingress

metadata:
  name: https-ingress

spec:
  ingressClassName: nginx

  tls:
  - hosts:
    - demo.local

    secretName: demo-tls

  rules:
  - host: demo.local

    http:
      paths:
      - path: /
        pathType: Prefix

        backend:
          service:
            name: nginx-service

            port:
              number: 80
```

# 二十三、Canary Ingress

## canary-ingress.yaml

```
apiVersion: networking.k8s.io/v1
kind: Ingress

metadata:
  name: canary-ingress

  annotations:
    nginx.ingress.kubernetes.io/canary: "true"

    nginx.ingress.kubernetes.io/canary-weight: "20"

spec:
  ingressClassName: nginx

  rules:
  - host: demo.local

    http:
      paths:
      - path: /
        pathType: Prefix

        backend:
          service:
            name: nginx-v2-service

            port:
              number: 80
```

# 第一阶段：网络基础概念与核心组件（地基层）

这一阶段解决一个问题：

> Pod 为什么能通信？

因为本质上：

```
Pod ≈ Linux Network Namespace
```

K8s 网络其实就是 Linux 网络能力的组合。

如果 Linux 网络不懂：

```
Namespace
veth
bridge
route
iptables
VXLAN
```

后面：

```
Pod
Service
CNI
Flannel
Calico
```

全部会变成黑盒。

# 第一层：Network Namespace

------

## 什么是 Namespace

Linux 内核提供的一种隔离机制。

例如：

```
PID Namespace
Mount Namespace
IPC Namespace
UTS Namespace
Network Namespace
```

其中：

```
Network Namespace
```

用于隔离：

```
网卡
IP
路由表
ARP表
iptables
```

------

## 看宿主机网络

```
ip addr
```

例如：

```
eth0 192.168.10.100
lo   127.0.0.1
```

------

## 创建一个 Namespace

```
ip netns add pod1
```

查看：

```
ip netns list
```

输出：

```
pod1
```

------

进入 namespace 查看网卡：

```
ip netns exec pod1 ip addr
```

结果：

```
lo
```

只有：

```
lo
```

因为这是一个全新的网络世界。

------

# 为什么 Pod 本质就是 Namespace

容器启动时：

```
docker
containerd
CRI-O
```

都会创建：

```
Network Namespace
```

例如：

```
Pod A
↓
netns A

Pod B
↓
netns B
```

彼此网络完全隔离。

------

# 验证

宿主机：

```
ping 192.168.10.100
```

namespace：

```
ip netns exec pod1 ping 192.168.10.100
```

会发现：

```
Network is unreachable
```

因为：

```
没有网卡
没有路由
```

```

```

```

```

```

```

```
宿主机
  |
veth0
  |
=================

veth1
  |
pod1
```

```

```

```

```

# 五链

```
PREROUTING
INPUT
FORWARD
OUTPUT
POSTROUTING
```

## 顺序（数据包走的路径）

**PREROUTING → INPUT/FORWARD → OUTPUT → POSTROUTING**

#### 1. 五大链作用

1. **PREROUTING 路由前**

   数据包**刚进网卡**，还没判断去哪

   - 最常用：**DNAT 目的地址转换**
   - K8s 访问 ClusterIP 就在这里改目标 IP

2. **INPUT 入站**

   数据包**目标是本机**，进本机进程

   - 本机端口放行、拦截

3. **FORWARD 转发**

   数据包**不是给本机**，只是路过本机转发

   - 同节点 Pod 互通、跨节点转发走这里

4. **OUTPUT 出站**

   **本机发出**的数据包，往外走

5. **POSTROUTING 路由后**

   数据包**快要离开网卡**最后一关

   - 最常用：**SNAT 源地址转换**

------

#### 2. 三种流量走法（秒懂）

##### ① 访问本机服务

外网 → **PREROUTING** → **INPUT** → 本机程序

##### ② 本机往外发数据

本机程序 → **OUTPUT** → **POSTROUTING** → 外网

##### ③ 路过本机转发（K8s 最常用）

外网 → **PREROUTING** → **FORWARD** → **POSTROUTING** → 其他机器

------

#### 3. K8s Service 流量核心流程（iptables 模式）

1. 访问 **ClusterIP** 流量进来
2. **PREROUTING** 做 DNAT：把 ClusterIP 改成 **Pod 真实 IP**
3. 走 **FORWARD** 转发
4. **POSTROUTING** 做 SNAT 改源 IP
5. 到达后端 Pod

------

# 流量路径

外部数据包 → 访问**本机进程**

```
网卡
 ↓
PREROUTING
 ↓
路由判断
 ↓
INPUT
 ↓
进程
```

------

数据包**路过本机**（转发，K8s 最常用）

```
PREROUTING
   ↓
路由判断（目标不是本机）
   ↓
FORWARD（转发链）
   ↓
POSTROUTING（路由后）
   ↓
发出网卡
```

```
Node
```

# 第六层：VXLAN

------

这是跨节点 Pod 通信核心。

------

## 问题

Node1：

```
10.244.1.2
```

Node2：

```
10.244.2.3
```

交换机不认识：

```
10.244.x.x
```

怎么办？

------

## VXLAN思想

把 Pod 包：

```
IP包
```

再包一层：

```
UDP
```

发送。

------

原包：

```
10.244.1.2
 ↓
10.244.2.3
```

封装后：

```
192.168.1.10
 ↓
192.168.1.20
 UDP 4789
```

------

# VTEP

VXLAN Tunnel Endpoint

例如：

```
Node1
flannel.1

Node2
flannel.1
```

------

负责：

```
封装
解封装
```

# 第一阶段核心结论

你必须记住一句话：

```
Pod = Network Namespace

Pod网卡 = veth

Node内部交换机 = cni0 bridge

跨节点通信 = route + VXLAN/BGP

Service转发 = iptables/IPVS/eBPF
```

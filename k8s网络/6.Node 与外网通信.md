# 阶段六：Node 与外网通信（Kubernetes 网络最终拼图）

到这里，你已经掌握了：

```
Pod ↔ Pod
Pod ↔ Service
Node ↔ Node
```

最后一块拼图是：

```
Pod ↔ Internet
Internet ↔ Pod
```

实际上整个 Kubernetes 网络最终都在解决两个问题：

```
出去（Egress）
回来（Ingress）
```

------

# 第一部分：Pod 如何访问 Internet

假设：

```
PodA
10.244.1.2
```

访问：

```
www.baidu.com
220.181.xx.xx
```

------

## 问题

Pod IP：

```
10.244.1.2
```

属于：

```
RFC1918 私网地址
```

公网路由器根本不知道：

```
10.244.1.2
```

在哪里。

所以：

```
Pod 不能直接使用自己的 IP 上网
```

必须：

```
SNAT
```

------

# SNAT 原理

原始数据包：

```
SRC:
10.244.1.2

DST:
220.181.xx.xx
```

------

经过 Node：

```
192.168.1.10
```

执行：

```
SNAT
```

变成：

```
SRC:
192.168.1.10

DST:
220.181.xx.xx
```

------

公网看到：

```
请求来自 Node
```

而不是：

```
Pod
```

------

# Kubernetes 如何实现 SNAT

查看：

```
iptables -t nat -L POSTROUTING -n
```

常见：

```
MASQUERADE
all
10.244.0.0/16
```

------

本质：

```
Pod网段
↓
离开节点
↓
改源IP
↓
NodeIP
```

------

# MASQUERADE

Linux 提供的动态 SNAT。

例如：

```
iptables -t nat \
-A POSTROUTING \
-s 10.244.0.0/16 \
-j MASQUERADE
```

------

含义：

```
凡是来自：

10.244.0.0/16

离开本机

↓

自动改成 eth0 IP
```

------

假设：

```
Pod

Gateway
192.168.1.1

```

------

路径：

```

     |

     v

     |

     |

     |
     |
     v

     |
     |
     v

10.244.1.2

     |
     |
     v

     |

------

# 验证

进入 Pod：

```
kubectl exec -it pod1 -- curl ifconfig.me
```

返回：

```
192.168.1.10
```

而不是：

```
10.244.1.2
```

说明：

```
SNAT 成功
```

# 第二部分：为什么 Internet 不能直接访问 Pod

假设：

```
Pod
10.244.1.2
```

------

公网用户：

```
curl 10.244.1.2
```

失败。

------

原因1：

```
私有地址
```

------

原因2：

```
互联网没有
10.244.0.0/16
路由
```

------

原因3：

```
Node不会主动把流量转发给Pod
```

------

因此：

```
需要入口
```

例如：

```
NodePort
LoadBalancer
Ingress
```

------

# 第三部分：NodePort

最简单的外部入口。

------

创建：

```
kind: Service
spec:
  type: NodePort
```

------

例如：

```
Service
ClusterIP:
10.96.0.10

NodePort:
30080
```

------

Node：

```
192.168.1.10
```

------

访问：

```
curl http://192.168.1.10:30080
```

------

# NodePort 数据路径

用户：

```
1.2.3.4
```

访问：

```
192.168.1.10:30080
```

------

kube-proxy：

iptables：

```
NODEPORT
↓
SERVICE
↓
ENDPOINT
```

------

最终：

```
10.244.1.2:80
```

------

完整路径：

```
Internet

   |
   |
   v

NodeIP:30080

   |
   |
   v

KUBE-NODEPORTS

   |
   |
   v

KUBE-SERVICES

   |
   |
   v

DNAT

10.96.0.10
     ↓
10.244.1.2

   |
   |
   v

Pod
```

------

# 查看规则

# 第五部分：Ingress

生产环境主流方案。

------

很多新人：

```
一个服务
一个 LoadBalancer
```

结果：

```
100个服务
100个公网IP
```

成本爆炸。

------

Ingress：

```
一个 LB
↓
一个 Nginx Controller
↓
100个域名
↓
100个服务
```

------

假设：

```
api.demo.com
```

------

```
api.demo.com
↓
47.100.x.x
```

------

路径：

```
Browser

    |
    |
    v

    |
    |
    v

    |
    |
    v

    |
    |
    v

```

```

# Cluster 模式

假设：

```
Node1
有 Pod

Node2
没 Pod
```

------

LB：

流量打到：

```
Node2
```

------

Node2：

再次转发：

```
Node1
```

------

路径：

```
LB
 ↓
Node2
 ↓
Node1
 ↓
Pod
```

------

特点：

```
可能多一次节点跳转
```

------

同时：

可能 SNAT：

```
客户端真实IP丢失
```

------

# Local 模式

LB：

只发送给：

```
拥有 Pod 的 Node
```

------

路径：

```
LB
 ↓
Node1
 ↓
Pod
```

------

特点：

```
无额外转发
保留真实客户端IP
```

------

缺点：

```
流量分布可能不均
```

# 阶段六核心结论

整个 Kubernetes 网络最终只有两件事：

------

## 出去

```
Pod
 ↓
Route
 ↓
SNAT(MASQUERADE)
 ↓
NodeIP
 ↓
Internet
```

核心：

```
SNAT
```

------

## 进来

```
Internet
 ↓
LB/NodePort/Ingress
 ↓
Service
 ↓
DNAT
 ↓
Pod
```

核心：

```
DNAT
```

# 六阶段学习后的最终认知

如果把 Kubernetes 网络压缩成一句话：

```
Kubernetes 网络
=
Linux Namespace
+ veth
+ Bridge
+ Route
+ iptables/eBPF
+ VXLAN/BGP
```

对应关系：

| Kubernetes概念 | Linux本质            |
| -------------- | -------------------- |
| Pod            | Network Namespace    |
| Pod网卡        | veth                 |
| Node内部交换   | cni0 Bridge          |
| Pod跨节点      | VXLAN/BGP            |
| Service        | DNAT                 |
| Pod出网        | SNAT                 |
| Ingress        | Nginx/Envoy 七层代理 |
| NetworkPolicy  | iptables/eBPF ACL    |
| Cilium         | eBPF 数据平面        |
| kube-proxy     | Service 转发表生成器 |

这张表如果你能脱离资料完整讲出来，并且配合：

```
ip netns
ip route
bridge fdb
iptables
tcpdump
conntrack
```

进行现场演示，那么对于 Kubernetes 网络而言，你已经从“会用”进入了“理解原理并具备排障能力”的阶段。

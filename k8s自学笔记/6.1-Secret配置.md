# 一、最基础的 Secret YAML

这是最核心模板：

```
apiVersion: v1
kind: Secret

metadata:
  name: mysql-secret

type: Opaque

data:
  username: cm9vdA==
  password: MTIzNDU2
```

------

# 二、先解释每一部分

## 1. kind: Secret

表示：

```
这是一个 Secret 资源
```

------

## 2. type: Opaque

表示：

```
普通 Secret
```

最常用。

------

## 3. data

这里存：

```
key-value
```

例如：

```
username: cm9vdA==
password: MTIzNDU2
```

注意：

```
必须 Base64
```

------

# 三、为什么是乱码？

例如：

```
root
```

编码：

```
echo -n "root" | base64
```

结果：

```
cm9vdA==
```

------

## password

```
echo -n "123456" | base64
```

结果：

```
MTIzNDU2
```

------

# 四、部署 Secret

保存：

```
secret.yaml
```

部署：

```
kubectl apply -f secret.yaml
```

查看：

```
kubectl get secret
```

结果：

```
mysql-secret
```

------

# 五、查看 Secret

```
kubectl get secret mysql-secret -o yaml
```

会看到：

```
data:
  password: MTIzNDU2
```

------

# 六、解码查看

```
echo MTIzNDU2 | base64 -d
```

结果：

```
123456
```

------

# 七、真正企业更喜欢 stringData

这是重点。

企业里：

```
很少手动 Base64
```

因为太麻烦。

所以通常写：

```
apiVersion: v1
kind: Secret

metadata:
  name: mysql-secret

type: Opaque

stringData:
  username: root
  password: 123456
```

------

# 八、stringData 和 data 区别

| 字段       | 是否需要Base64 |
| ---------- | -------------- |
| data       | 需要           |
| stringData | 不需要         |

------

# 九、K8s 会自动转换

你写：

```
stringData:
  password: 123456
```

K8s 实际保存：

```
data:
  password: MTIzNDU2
```

自动编码。

所以：

```
开发最推荐：
stringData
```

# 十、Secret 注入 Pod（重点）

------

# 方式1：环境变量

## pod.yaml

```
apiVersion: v1
kind: Pod

metadata:
  name: mysql-pod

spec:
  containers:
  - name: mysql
    image: mysql:5.7

    env:
    - name: MYSQL_ROOT_PASSWORD

      valueFrom:
        secretKeyRef:
          name: mysql-secret
          key: password
```

------

# 这里发生了什么？

```
mysql-secret
↓
取 password
↓
赋值给环境变量
↓
MYSQL_ROOT_PASSWORD=123456
```

------

# 十一、进入 Pod 查看

```
kubectl exec -it mysql-pod -- bash
```

查看：

```
echo $MYSQL_ROOT_PASSWORD
```

结果：

```
123456
```

------

# 十二、方式2：Volume 挂载（企业推荐）

------

# Secret

```
stringData:
  username: root
  password: 123456
```

------

# Pod

```
apiVersion: v1
kind: Pod

metadata:
  name: secret-volume-pod

spec:
  containers:
  - name: nginx
    image: nginx

    volumeMounts:
    - name: secret-volume
      mountPath: /etc/secret

  volumes:
  - name: secret-volume

    secret:
      secretName: mysql-secret
```

------

# 十三、挂载后会发生什么？

容器里：

```
/etc/secret/username
/etc/secret/password
```

------

# 查看：

```
cat /etc/secret/password
```

结果：

```
123456
```

------

# 十四、你必须理解的本质

这是重点。

Secret Volume：

```
本质：
把 key 变成文件名
把 value 变成文件内容
```

即：

| key      | 文件                 |
| -------- | -------------------- |
| username | /etc/secret/username |
| password | /etc/secret/password |

------

# 十五、ConfigMap 对比（非常重要）

其实：

```
Secret 和 ConfigMap 用法几乎一样
```

例如：

------

# ConfigMap

```
apiVersion: v1
kind: ConfigMap

metadata:
  name: app-config

data:
  app.yaml: |
    server:
      port: 8080
```

------

# Secret

```
apiVersion: v1
kind: Secret

metadata:
  name: app-secret

stringData:
  password: 123456
```

------

# 它们都能：

| 功能       | ConfigMap | Secret |
| ---------- | --------- | ------ |
| env注入    | ✓         | ✓      |
| volume挂载 | ✓         | ✓      |
| key-value  | ✓         | ✓      |

真正区别：

```
Secret = 敏感配置
```

------

# 十六、TLS Secret（Ingress 必学）

HTTPS：

```
必须用 Secret
```

创建：

```
kubectl create secret tls nginx-tls \
--cert=tls.crt \
--key=tls.key
```

会生成：

```
type: kubernetes.io/tls
```

------

# Ingress 使用

```
tls:
- hosts:
  - example.com

  secretName: nginx-tls
```

# 十八、面试重点（非常高频）

------

# 1. Secret 为什么要 Base64？

标准答案：

```
K8s API 要求 data 字段使用 Base64。
但这不是加密。
```

------

# 2. Secret 和 ConfigMap 区别？

```
本质都属于 key-value 配置资源。

ConfigMap：
普通配置

Secret：
敏感配置
```

------

# 3. Secret 注入方式？

```
env
volume
```

------

# 4. 企业为什么喜欢 Volume？

```
避免环境变量泄露
```

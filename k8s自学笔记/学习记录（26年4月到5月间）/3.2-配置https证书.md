# http怎么配证书变成https1

你可以把它理解成：

```
HTTP + SSL/TLS 证书 = HTTPS
```

也就是说：

```
客户端（浏览器）
    ↓
TLS 加密
    ↓
Nginx / Ingress
    ↓
HTTP 服务
```

------

# 一、HTTPS 到底干了什么？

HTTP 是明文：

```
账号=admin
密码=123456
```

中间人能直接抓包看到。

HTTPS 会：

- 加密数据
- 防止被篡改
- 验证服务器身份

核心就是：

```
TLS 证书
```

------

# 二、HTTPS 的本质流程

浏览器访问：

```
https://example.com
```

服务器会：

1. 把证书发给浏览器
2. 浏览器验证证书是否合法
3. 双方协商加密密钥
4. 后续通信全部加密

------

# 三、证书是什么？

本质是两个文件：

```
公钥
私钥
```

通常表现为：

```
server.crt
server.key
```

或者：

```
fullchain.pem
privkey.pem
```

------

# 四、最经典：Nginx 配 HTTPS

假设：

```
域名：
example.com
```

证书：

```
/etc/nginx/ssl/server.crt
/etc/nginx/ssl/server.key
```

------

## 1. 配置 HTTP

原来：

```
server {
    listen 80;

    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

------

## 2. 改成 HTTPS

```
server {
    listen 443 ssl;

    server_name example.com;

    ssl_certificate     /etc/nginx/ssl/server.crt;
    ssl_certificate_key /etc/nginx/ssl/server.key;

    location / {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

------

## 3. 重启 Nginx

```
nginx -t
systemctl restart nginx
```

------

# 五、HTTP 自动跳 HTTPS（企业必配）

通常还会：

```
http://example.com
自动跳转
https://example.com
```

配置：

```
server {
    listen 80;
    server_name example.com;

    return 301 https://$host$request_uri;
}
```

# 六、证书哪里来？

## 方案1：自己生成（学习用）

```
openssl req -x509 -nodes -days 365 \
-newkey rsa:2048 \
-keyout server.key \
-out server.crt
```

生成：

```
server.crt
server.key
```

但浏览器会：

```
不安全
```

因为不是权威 CA 签发。

certbot

# 八、K8s 里的 HTTPS（重点）

你后面学 Ingress 会大量用。

K8s 里：

```
Ingress + TLS Secret
```

实现 HTTPS。

------

# 九、K8s HTTPS 核心流程

## 1. 创建证书 Secret

```
kubectl create secret tls nginx-tls \
--cert=server.crt \
--key=server.key
```

会生成：

```
Secret:
type: kubernetes.io/tls
```

------

## 2. Ingress 使用 TLS

```
apiVersion: networking.k8s.io/v1
kind: Ingress

metadata:
  name: nginx-ingress

spec:
  tls:
  - hosts:
    - example.com

    secretName: nginx-tls

  rules:
  - host: example.com

    http:
      paths:
      - path: /
        pathType: Prefix

        backend:
          service:
            name: nginx-service
            port:
              number: 80
```

这里核心：

```
tls:
```

和：

```
secretName:
```

这就是企业最常见架构。

## 一、 核心安全基石：数据加密与身份认证

### 1. 公钥私钥 (Public Key & Private Key)

这是**非对称加密**的核心。它们是成对生成的钥匙：

- **公钥（Public Key）：** 公开给全世界的。任何人都可以用你的公钥来加密数据，或者用它来验证你的数字签名。
- **私钥（Private Key）：** 必须严格保密的。只有你持有，用来解密由对应公钥加密的数据，或者对数据进行签名。

> **核心逻辑：** 用公钥加密的数据，只有对应的私钥能解开（保证机密性）；用私钥签名的数据，任何人用公钥都能验证其来源（保证不可篡改和身份认证）。

### 2. 证书 (Digital Certificate / CA Certificate)

公钥是公开的，但你怎么证明“这个公钥确实属于百度，而不是黑客伪造的”？

- **数字证书**就是网络世界的“身份证”。它由权威的第三方机构（CA，证书颁发机构）签发。
- 证书里面包含了：**网站的域名、网站的公钥**，以及 CA 机构的数字签名。
- 浏览器内置了信任的 CA 机构列表，可以通过验证证书上的签名，确保这个公钥的真实性。

### 3. SSL/TLS

这是网络传输加密的**协议标准**。

- **SSL (Secure Sockets Layer)：** 安全套接层，是旧版本的加密协议。
- **TLS (Transport Layer Security)：** 传输层安全，是 SSL 的升级版和继任者。由于历史习惯，现在大家常把它们统称为 SSL/TLS。
- **它的作用：** 在 TCP 握手之后，利用**公钥私钥**和**证书**，在客户端（浏览器）和服务器之间协商出一套“对称加密密钥”，此后双方的所有流量都用这个对称密钥进行高速加密传输。

## 二、 网络协议与应用端口

### 4. HTTP (HyperText Transfer Protocol)

- **超文本传输协议**，是互联网上应用最广泛的一种网络协议。
- 它是**明文传输**的。这意味着你在网页上输入的密码、信用卡号，在网络传输过程中如果被黑客截获，可以直接被看光（中间人攻击）。

### 5. HTTPS (HTTP Secure)

- **安全的 HTTP**。简单来说，就是 **HTTP + SSL/TLS**。
- HTTPS 不再直接把明文塞给 TCP 传输，而是先经过 SSL/TLS 层加密，然后再传给下层。这样即使网络数据包被截获，黑客看到的也只是无法破解的乱码。

### 6. 443 (端口)

- 端口是服务器区分不同服务的编号。
- **80 端口：** 默认分配给标准的 **HTTP** 协议。
- **443 端口：** 默认分配给 **HTTPS** 协议。当你在浏览器输入 `https://` 时，浏览器会自动去连接服务器的 443 端口。

## 三、 Kubernetes (K8s) 云原生落地实践

当你把上述概念放到 Kubernetes 集群中去实现时，就对应到了最后两个概念。

### 7. TLS Secret

- 在 Kubernetes 中，**Secret** 是用来存储敏感数据（如密码、令牌、密钥）的对象。
- **TLS Secret** 是一种特定类型的 Secret，它专门用来**存放服务器的“证书(Certificate)”和“私钥(Private Key)”**。
- 你需要把从证书服务商那里下载到的 `.crt`（证书）和 `.key`（私钥）文件，打包创建成一个 K8s 的 TLS Secret，方便集群内的组件直接调用。

### 8. Ingress HTTPS

- **Ingress** 是 Kubernetes 的流量网关，负责把集群外部的请求（域名/路径）路由到集群内部的 Service。
- **Ingress HTTPS (TLS 终止/卸载)：** 1. 外部用户通过 **443 端口** 发起 **HTTPS** 请求访问你的网站。 2. 流量到达 **Ingress Controller**（如 Nginx Ingress）。 3. Ingress 会挂载你配置的 **TLS Secret**，利用里面的**私钥和证书**与用户完成 SSL/TLS 握手，并在网关处**解密**流量。 4. 解密后，Ingress 通常会以**明文 HTTP** 的形式，将请求转发给集群内部的 Pod（比如你的后端微服务）。

## 💡 总结：它们是如何串联起来的？

1. 开发者生成**公钥私钥**，向 CA 机构申请并拿到了**证书**。
2. 开发者把证书和私钥配置到了 K8s 的 **TLS Secret** 中。
3. 在 **Ingress** 路由规则中启用 **HTTPS**，并关联这个 **TLS Secret**。
4. 用户访问集群，请求通过 **443 端口** 以 **HTTPS** 协议（基于 **SSL/TLS**）安全地到达 Ingress。
5. Ingress 拆开安全包裹，把请求安全地分发到后面的具体服务中。

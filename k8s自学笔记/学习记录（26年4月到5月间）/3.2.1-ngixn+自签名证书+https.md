在虚拟机上用 Nginx 和自签名证书搭建 HTTPS 学习环境是一个非常经典的实验！它能帮你彻底理清证书生成、Nginx 监听以及浏览器信任的整个闭环。

因为是在学习环境，我们直接使用 **OpenSSL** 工具来充当“证书颁发机构（CA）”给自己签发证书。

以下是完整的实战步骤：

## 步骤一：在虚拟机上生成自签名证书

首先，我们需要生成**私钥**，然后用这个私钥生成**自签名证书**。你可以新建一个目录（如 `/etc/nginx/ssl`）来存放它们。

```bash
mkdir -p /etc/nginx/ssl && cd /etc/nginx/ssl
```

运行以下单条命令，即可同时生成私钥和证书（自签名）：

```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout mydomain.key \
  -out mydomain.crt \
  -subj "/C=CN/ST=Shanghai/L=Shanghai/O=Development/CN=mydomain.local"
```

**🔑 参数详解（知其然更要知其所以然）：**

- `req -x509`：指定生成自签名证书，而不是生成证书签名请求（CSR）。
- `-nodes`：数字是 "no DES" 的缩写，意思是**不对私钥加密**。这样 Nginx 启动时就不需要你手动输入密码了。
- `-days 365`：证书有效期为 365 天。
- `-newkey rsa:2048`：同时生成 2048 位的 RSA 私钥。
- `-keyout` 和 `-out`：分别指定生成的私钥（.key）**和**证书（.crt）的文件名。
- `-subj "..."`：直接在命令行指定证书的主体信息。其中 **`CN=mydomain.local`** 最重要，它是你的**虚拟域名**，后面我们用浏览器访问时就用这个。

执行完后，输入 `ls` 就会看到当前目录下多了 `mydomain.key` 和 `mydomain.crt`。

## 步骤二：在宿主机准备好文件

为了不让 Docker 内部的配置文件丢失，我们先在虚拟机的宿主机上建好目录，并把证书和配置放进去。

### 1. 证书文件

我们沿用刚才生成的证书。如果你已经把证书生成在 `/etc/nginx/ssl` 了，那就保持原样。

- 证书路径：`/etc/nginx/ssl/mydomain.crt`
- 私钥路径：`/etc/nginx/ssl/mydomain.key`

### 2. 编写 Nginx 配置文件

在宿主机新建一个目录用来放配置，例如 `/etc/nginx/conf.d`：

Bash

```
mkdir -p /etc/nginx/conf.d
```

在这个目录下创建一个 `default.conf` 文件：

Bash

```
vi /etc/nginx/conf.d/default.conf
```

写入以下内容（注意：**这里的证书路径要填容器内部的路径**，后面我们会做映射）：

Nginx

```
server {
    listen 80;
    listen 443 ssl;
    server_name mydomain.local;

    # 这里的路径是容器内部的虚拟路径
    ssl_certificate     /etc/nginx/ssl/mydomain.crt;
    ssl_certificate_key /etc/nginx/ssl/mydomain.key;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location / {
        root   /usr/share/nginx/html; # Nginx 镜像默认的静态页面目录
        index  index.html index.htm;
    }
}
```

## 步骤三：启动 Docker 容器

万事俱备，运行以下 `docker run` 命令。这行命令看起来有点长，但里面有 3 个关键的`-v`（挂载）参数：

Bash

```
docker run -d \
  --name my-https-nginx \
  -p 80:80 \
  -p 443:443 \
  -v /etc/nginx/conf.d:/etc/nginx/conf.d \
  -v /etc/nginx/ssl:/etc/nginx/ssl \
  nginx:1.25
```

**🐳 命令拆解：**

- `-d`：后台运行容器。
- `-p 80:80` 和 `-p 443:443`：把宿主机的 80 和 443 端口，映射到 Docker 容器的 80 和 443 端口。
- **`-v /etc/nginx/conf.d:/etc/nginx/conf.d`**：把宿主机的配置目录挂载到容器内，这样 Nginx 启动时就能读取到你刚才写的 `default.conf`。
- **`-v /etc/nginx/ssl:/etc/nginx/ssl`**：把宿主机存放证书的目录挂载到容器内，容器里的 Nginx 就能找到 `.crt` 和 `.key` 文件了。

启动后，可以用 `docker ps` 查看容器是否正常运行。

## 💡 踩坑与调试指南

用 Docker 玩这个实验时，最容易遇到“容器闪退”**或者**“修改了配置不生效”的问题，教你两个绝招：

1. **如果容器没启动成功（`docker ps` 看不到）：** 运行 `docker logs my-https-nginx` 查看报错日志。通常是因为 `default.conf` 里的语法写错了，或者是证书路径跟你在 `-v` 参数里映射的不一致，导致 Nginx 找不到证书。

2. **如果你修改了宿主机上的 `default.conf`：** 不需要重启整个 Docker 容器，直接让容器内的 Nginx 热重载（reload）即可，非常优雅：

   Bash

   ```
   docker exec -it my-https-nginx nginx -s reload
   ```

接下来，你同样可以在本地电脑（宿主机）配置好 Hosts，然后用浏览器访问 `https://mydomain.local` 测试效果了！

## 步骤四：本地宿主机（电脑）访问与避坑指南

由于我们在证书中指定的域名是 `mydomain.local`，并且服务运行在虚拟机里，直接在本地电脑的浏览器输入它是无法访问的。我们需要做两件事：**配置 Hosts** 和 **处理证书信任**。

### 1. 配置本地 Hosts（域名解析）

在你的物理机（真实电脑）上修改 Hosts 文件，将域名的解析指向虚拟机的 IP。

- **Windows 路径：** `C:\Windows\System32\drivers\etc\hosts`
- **Mac/Linux 路径：** `/etc/hosts`

在文件末尾添加一行（假设你的虚拟机 IP 是 `192.168.56.101`）：

Plaintext

```
192.168.56.101 mydomain.local
```

### 2. 浏览器访问与“安全警告”

现在打开你物理机上的浏览器，输入：`https://mydomain.local`

你一定会看到一个红色的警告页面，提示 **“您的连接不是私密连接” (NET::ERR_CERT_AUTHORITY_INVALID)**。

- **为什么？** 因为这个证书是你自己签发的，不是由操作系统内置的权威 CA（如 DigiCert, Let's Encrypt）签发的，浏览器不认识你。
- **怎么解决？** * **临时通过：** 点击页面上的 **“高级” (Advanced)** -> 点击 **“继续前往 mydomain.local（不安全）”**，即可正常看到你的网页（此时地址栏会显示红色的“不安全”或一把带红线的锁，但流量确实已经是 HTTPS 加密了）。
  - **完美解决（可选）：** 把你在虚拟机生成的 `mydomain.crt` 文件下载到物理机上，双击它，将其安装到操作系统的“受信任的根证书颁发机构”**中。重启浏览器再访问，红色的警告就会变成代表安全的**绿色小锁。

## 💡 进阶小练习（可选）

既然配置了 HTTPS，建议顺手再配一个 **HTTP 自动跳转 HTTPS**。当用户误输入 `http://mydomain.local` 时，自动强制跳转到安全连接。

修改刚才的 Nginx 配置，把 80 端口和 443 端口拆开：

Nginx

```
# 负责处理 HTTP 请求并重定向
server {
    listen 80;
    server_name mydomain.local;
    return 301 https://$host$request_uri; 
}

# 负责处理 HTTPS 请求
server {
    listen 443 ssl;
    server_name mydomain.local;

    ssl_certificate     /etc/nginx/ssl/mydomain.crt;
    ssl_certificate_key /etc/nginx/ssl/mydomain.key;
    
    # ... 其他保持不变 ...
}
```

实验过程中如果在哪个步骤（比如证书生成、Nginx 报错或者 Hosts 没生效）卡住了，随时把报错信息发出来，我们一起排查！

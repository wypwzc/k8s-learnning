## 🛠️ 核心架构演进：从“内网自嗨”到“公网发布”

### 1. 为什么把 TLS 证书配在云服务器上更好？

如果把公网证书（比如你买的真实域名证书）配在最外层的云服务器（Nginx）上：

- **证书管理极简**：你只需要在云服务器上用 `Certbot` 或手工维护证书，不需要把证书打包同步到私有网络里的 K8s 里面。
- **安全卸载 (TLS Termination)**：云服务器作为“挡箭牌”，在公网把 HTTPS 流量解密。它和内部 K8s 集群之间走纯 HTTP 流量，能帮 K8s 节点省下大量用于加密解密的 CPU 算力。

## 🚀 两种主流的“映射”实战方案

你的 Windows/CentOS 虚拟机在家里（私网，没有公网 IP），云服务器在腾讯云/阿里云（公网）。要把家里的 K8s 映射出去，有两种主流玩法：

### 方案 A：内网穿透（低成本、适合个人实验）

利用 **frp (Fast Reverse Proxy)** 或 **FRPd / Cloudflare Tunnels** 等工具，在你的 CentOS 虚拟机和云服务器之间搭建一条加密的“地下隧道”。

- **数据流转**： 用户浏览器 (`https://你的真实域名`) → 云服务器 (Nginx 监听 443 端口，拿着 TLS 证书解密) → 通过 **frp 隧道** 把明文流量转发到家里的虚拟机 → 家里的 K8s Ingress (此时 Ingress 只需要听 HTTP 80 端口即可)

### 方案 B：正规军玩法（企业级：VPN 专线 / 隧道）

在云服务器和家里的网关之间建立一个 **WireGuard** 或 **IPsec VPN** 隧道，让云服务器和你的物理机局域网（`192.168.36.x`）在网络层直接拼通。 云服务器上的 Nginx 直接配置：

Nginx

```
proxy_pass http://192.168.36.137:30539; # 对应你之前的 Ingress HTTP NodePort 端口
```

## 📝 云服务器上的 Nginx 配置长啥样？

如果你租了云服务器，并且配置好了网络映射，云服务器上的 Nginx 核心配置（`/etc/nginx/nginx.conf`）基本长这样：

Nginx

```
server {
    listen 80;
    server_name www.yourdomain.com;
    # 强制将所有公网 HTTP 流量重定向到 HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name www.yourdomain.com;

    # 在云服务器本地存放并配置你的真实 TLS 证书
    ssl_certificate /etc/nginx/ssl/yourdomain.crt;
    ssl_certificate_key /etc/nginx/ssl/yourdomain.key;

    location / {
        # 核心：将流量反向代理到你家里的 K8s 节点物理 IP 和 Ingress 的 HTTP 映射端口
        # 假设你通过内网穿透把家里的 30539(HTTP) 映射到了云服务器本地的 8080 端口
        proxy_pass http://127.0.0.1:8080; 
        
        # 传递真实客户端 IP 极其重要（防止 K8s 看到的全部是云服务器的 IP）
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 1. 物理版图：资源都在哪？

你的这套系统横跨了两个完全不同的物理世界：

- **云端（公网暴露层）**：
  - **云服务器**：拥有固定的公网 IP（如 `1.2.3.4`），是外界访问的唯一入口。
  - **真实域名**：如 `app.yourdomain.com`，解析到云服务器 IP。
  - **公网 TLS 证书**：由权威机构签发，安装在云服务器的 Nginx 上，浏览器完全信任。
- **家里（私有计算层）**：
  - **你的电脑**：用来通过浏览器访问测试，开着 VPN 也没关系。
  - **虚拟机集群（K8s）**：处于 `192.168.36.x` 的内网环境，没有公网 IP，在外面直接访问不到。

## 2. 管道建设：隧道是怎么打通的？

这是最精妙的地方，利用 `frp` 在公网和私网之间拉一根虚拟的“网线”：

1. 服务端（frps）在云服务器上启动，守住 `7000` 端口，等待家里老乡来认亲。
2. **客户端（frpc）\**在家里 K8s Master 上启动，主动向外发起连接，通过公网抓牢云服务器的 `7000` 端口，建立一条\**持久安全的双向死隧道**。
3. **铺设路轨**：我们在 `frpc` 里规定，只要云服务器的 `8080` 端口收到流量，就通过这条隧道立刻空投到家里 K8s Master 的 `30539` 端口（Ingress 的 HTTP 端口）。

## 3. 终极数据流向（全链路拆解）

当你在世界的任何一个角落，用手机或电脑浏览器输入 `https://app.yourdomain.com` 时，数据经历了一场奇妙的“漂流记”：

### 1. 公网导航阶段

- **浏览器**：向 DNS 服务器询问 `app.yourdomain.com` 是谁？
- **DNS 服务器**：返回云服务器的公网 IP `1.2.3.4`。
- **浏览器**：带着加密请求，奔向 `1.2.3.4:443`。

### 2. 云端解密与代理阶段

- **云服务器 Nginx**：迎客！掏出真实的 TLS 证书和浏览器完成握手（**TLS 在这里终止，变成明文**）。
- **云服务器 Nginx**：根据配置，把解密后的明文 HTTP 请求，顺手转给本地的 `127.0.0.1:8080`。

### 3. 隧道穿透阶段

- **云服务器 frps**：在 `8080` 端口截获流量，心领神会，直接把数据打包，塞进早就建好的 frp 专属加密隧道。
- **家里 Master frpc**：在虚拟机里收到隧道那头传过来的数据包，解包，直接拍到本地的 `30539` 端口（K8s Ingress Controller）。

### 4. K8s 内部冲刺阶段

- **Ingress Controller**：收到流量，一看 HTTP Header 里的域名是 `app.yourdomain.com`，匹配路由规则，转发给内网 Service `web-app-service:80`。
- **Service**：通过内部负载均衡，把流量递给处于 Running 状态的 **Pod**。
- **Pod**：读取 ConfigMap 里的 HTML 和 Opaque Secret 里的数据库密码，高高兴兴地吐出网页内容。

### 5. 原路返回

- 数据沿着：**Pod → Ingress → frpc → frps → Nginx（重新加密成 HTTPS）→ 浏览器**。
- 你的浏览器瞬间刷新，绿色的安全锁头高高挂起，显示出 **"Hello from Kubernetes!"**。

## 💡 为什么这个架构能被称为“教科书级”？

1. **绝对的安全**：你家里的 K8s 集群没有暴露任何端口给公网，黑客连你家虚拟机的 IP 都不知道，云服务器成了你最硬的盾牌。
2. **完美的避坑**：因为 TLS 在云服务器就终结了，你本地 Windows 开不管什么 VPN 代理，都不可能劫持你对公网域名的访问，彻底告别了“网络鬼打墙”。
3. **无限的扩展**：以后你家里如果再部署新的服务（比如博客、网盘），只需要在 K8s 里加几行 Ingress 规则，在云服务器 Nginx 里加个反向代理，就能用同一个隧道全部发布出去！

## 🏁 落地开干的最后 3 项微调检查

既然你的域名 `wzcwyp.xyz` 已经就位，接下来实操时，只需要把我们之前聊到的配置做最后一次“对齐”：

### 1. DNS 解析（去买域名的控制台）

添加一条 **A 记录**：

- 主机记录：`@`（代表直接访问 `wzcwyp.xyz`）或者 `app`（代表访问 `app.wzcwyp.xyz`）。
- 记录值：填写你的**云服务器公网 IP**。

### 2. 云服务器 Nginx 文件的 `server_name`

把 Nginx 配置文件里的域名改成你的专属域名：

Nginx

```
server_name wzcwyp.xyz; # 或者 app.wzcwyp.xyz
```

### 3. K8s 内部 `05-ingress.yaml` 的 `host`

同样，家里 K8s 的 Ingress 规则里也要改成这个域名，不然 Ingress-Nginx 认不出这是发给谁的：

YAML

```
spec:
  rules:
  - host: wzcwyp.xyz # 必须和你在浏览器输入的域名完全一致！
    http:
      paths:
      - path: /
```

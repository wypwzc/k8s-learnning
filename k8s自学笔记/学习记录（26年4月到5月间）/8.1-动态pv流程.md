**生产环境部署 Prometheus 必须用 PV/PVC 做持久化**，否则 Pod 重启/迁移后监控数据全丢。

## 一、为什么 Prometheus 必须持久化？

Prometheus 默认用 `emptyDir` 存 TSDB 时序数据，存在容器里：

plain

```plain
Prometheus Pod 重启 → 新容器新 emptyDir → 历史监控数据全丢
```

生产环境要求：

- Pod 漂移后数据还在
- 能保留历史数据（默认 15 天，可调）
- 能扩容存储

所以必须挂 PVC，把数据落到外部存储（NFS/云盘/Ceph）。

## 二、完整方案：NFS + SC 动态供给 + Helm 部署

### 前置条件

- NFS 服务器已就绪，比如 `192.168.1.100:/data/nfs`
- K8s 所有节点已安装 `nfs-utils`

### Step 1：部署 NFS Subdir External Provisioner（创建 SC）

这是官方推荐的 NFS 动态供给器，会自动为每个 PVC 在 NFS 上创建子目录。

bash

```bash
# 添加 Helm 仓库
helm repo add nfs-subdir-external-provisioner https://kubernetes-sigs.github.io/nfs-subdir-external-provisioner/
helm repo update

# 安装 provisioner，同时创建 StorageClass
helm install nfs-provisioner nfs-subdir-external-provisioner/nfs-subdir-external-provisioner \
  --set nfs.server=192.168.1.100 \
  --set nfs.path=/data/nfs \
  --set storageClass.name=nfs-client \
  --set storageClass.defaultClass=true \
  --set storageClass.reclaimPolicy=Retain \
  --set storageClass.archiveOnDelete=false \
  -n kube-system
```

验证：

bash

```bash
kubectl get sc
# NAME         PROVISIONER                                     RECLAIMPOLICY   VOLUMEBINDINGMODE   ALLOWVOLUMEEXPANSION   AGE
# nfs-client   k8s-sigs.io/nfs-subdir-external-provisioner   Retain          Immediate           true                   1m
```

> **关键点**：`reclaimPolicy: Retain` —— 即使删了 Prometheus 的 PVC，NFS 上的历史监控数据也会保留，不会误删。

------

### Step 2：Helm 部署 Prometheus（指定 PVC）

用 **kube-prometheus-stack**（官方推荐，包含 Prometheus + Alertmanager + Grafana）：

bash

```bash
# 添加仓库
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
```

创建自定义 values 文件：

yaml

```yaml
# prometheus-values.yaml
prometheus:
  prometheusSpec:
    # 关键：启用持久化
    storageSpec:
      volumeClaimTemplate:
        spec:
          storageClassName: nfs-client      # 使用刚才创建的 SC
          accessModes: ["ReadWriteOnce"]    # Prometheus 单实例用 RWO 即可
          resources:
            requests:
              storage: 50Gi                 # 根据数据量调整，建议 50Gi 起步

    # 数据保留时间（默认 15d，磁盘大可调）
    retention: "30d"
    retentionSize: "45GB"                   # 超过 45GB 自动清理老数据

# Alertmanager 也要持久化（否则告警状态丢失）
alertmanager:
  alertmanagerSpec:
    storage:
      volumeClaimTemplate:
        spec:
          storageClassName: nfs-client
          accessModes: ["ReadWriteOnce"]
          resources:
            requests:
              storage: 10Gi

# Grafana 持久化（否则仪表盘配置丢失）
grafana:
  enabled: true
  persistence:
    enabled: true
    storageClassName: nfs-client
    accessModes: ["ReadWriteOnce"]
    size: 10Gi
```

部署：

bash

```bash
helm install prometheus prometheus-community/kube-prometheus-stack \
  -f prometheus-values.yaml \
  -n monitoring \
  --create-namespace
```

## 三、手动部署方式（不用 Helm，理解原理）

如果你公司不用 Helm，手动部署时要自己写 PVC 和 StatefulSet。

### 1. 先创建 PVC（动态供给，自动出 PV）

yaml

```yaml
# prometheus-pvc.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: prometheus-data
  namespace: monitoring
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: nfs-client    # 指定 SC，自动创建 PV
  resources:
    requests:
      storage: 50Gi
```

bash

```bash
kubectl apply -f prometheus-pvc.yaml
```

### 2. Prometheus Deployment/StatefulSet 挂载

yaml

```yaml
# prometheus-deploy.yaml 片段
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: prometheus
  namespace: monitoring
spec:
  serviceName: prometheus
  replicas: 1
  template:
    spec:
      containers:
      - name: prometheus
        image: prom/prometheus:v2.45.0
        args:
          - '--config.file=/etc/prometheus/prometheus.yml'
          - '--storage.tsdb.path=/prometheus'    # 数据目录
          - '--storage.tsdb.retention.time=30d'
        volumeMounts:
        - name: prometheus-storage
          mountPath: /prometheus                 # 挂到数据目录
      volumes:
      - name: prometheus-storage
        persistentVolumeClaim:
          claimName: prometheus-data               # 引用 PVC
```

> ⚠️ **权限坑**：Prometheus 容器默认用 `nobody` 用户运行，NFS 挂载后可能没权限写。需要在容器里加 `securityContext`：
>
> yaml
>
> ```yaml
> securityContext:
>   runAsUser: 65534    # nobody
>   runAsGroup: 65534
>   fsGroup: 65534      # 关键：让挂载的卷对 nobody 可写
> ```

## 四、关键注意点（踩坑总结）

表格



| 坑点            | 解决方案                                                     |
| :-------------- | :----------------------------------------------------------- |
| **权限拒绝**    | 加 `securityContext.fsGroup: 65534`，或把 NFS 目录设为 `777` |
| **NFS 性能差**  | Prometheus 是写密集型，NFS 性能不如本地 SSD。数据量大时考虑本地盘 + `local` PV，或云盘 |
| **多副本问题**  | Prometheus 不支持多实例共享存储（不能 RWX 多写），要用 **Thanos** 或 **VictoriaMetrics** 做集群 |
| **数据膨胀**    | 默认 15 天保留，指标多的时候 50Gi 很快满。务必设置 `retentionSize` |
| **SC 回收策略** | 监控数据重要，SC 用 `Retain`，误删 PVC 数据还在 NFS 上       |

## 五、面试怎么答（实习生版）

> **问：部署 Prometheus 时存储怎么规划？**

答：

1. **必须持久化**，用 PVC 挂载外部存储，否则 Pod 重启数据丢失。
2. **用 StorageClass 动态供给**，配合 NFS Provisioner，用户只写 PVC，PV 自动创建。
3. **Helm 部署时**在 `values.yaml` 里配置 `storageSpec.volumeClaimTemplate`，指定 `storageClassName` 和容量。
4. **注意权限问题**，Prometheus 以 `nobody` 运行，需要 `fsGroup` 保证写入权限。
5. **数据保留策略**，通过 `--storage.tsdb.retention.time` 和 `retentionSize` 控制，防止磁盘打满。
6. **生产建议**：单实例用 NFS 或云盘 RWO；如果要高可用多副本，需要引入 Thanos 做对象存储 + 查询聚合，不能简单共享 PVC。

## 总结（面试版）

> **问：SC 怎么自动创建 PV？**

答：

1. SC 本身只是配置模板，定义了用哪个 `provisioner`。
2. 集群里运行着对应的 **Provisioner Pod**（如 NFS provisioner 或云厂商 CSI），它通过 **Watch 机制**监听 PVC 创建事件。
3. 当用户创建 PVC 并指定了该 SC 时，Provisioner 被触发，执行两个动作：**在存储后端创建实际资源**（如 NFS 子目录/云盘），**调用 K8s API 创建 PV 对象**。
4. K8s 自动完成 PV 与 PVC 的绑定，整个过程对用户透明。

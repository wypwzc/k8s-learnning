Kubernetes 蓝绿部署（Blue-Green Deployment）是一种发布策略，核心思想是：**同时维护两个完全相同的生产环境（Blue 和 Green），通过切换流量来实现零停机发布和快速回滚**。

------

## 核心原理

```plain
流量 100% → Blue（当前版本 v1）
            ↓
        部署 Green（新版本 v2）
            ↓
流量 100% → Green（新版本 v2）  ← 切换完成
            ↓
        Blue 保留（备用/回滚）
```

- **Blue**：当前运行的稳定版本（线上环境）
- **Green**：新版本部署的独立环境
- 切换时，将流量从 Blue 全部切到 Green
- 如果 Green 出现问题，**瞬间切回 Blue** 即可完成回滚

------

## 在 Kubernetes 中的实现方式

K8s 本身没有内置"蓝绿"资源，通常通过以下方式实现：

### 方式一：Service + Label 切换（最常用）

```yaml
# 两个完全独立的 Deployment
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-blue  # 当前版本
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
      version: blue
  template:
    metadata:
      labels:
        app: myapp
        version: blue
    spec:
      containers:
      - name: app
        image: myapp:v1

---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-green  # 新版本
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
      version: green
  template:
    metadata:
      labels:
        app: myapp
        version: green
    spec:
      containers:
      - name: app
        image: myapp:v2

---
# Service 通过 label 选择器控制流量走向
apiVersion: v1
kind: Service
metadata:
  name: myapp-service
spec:
  selector:
    app: myapp
    version: green   # ← 切换这里：blue ↔ green
  ports:
  - port: 80
```

**切换流量**：修改 Service 的 `selector.version` 从 `blue` 改为 `green`，K8s 会立即将流量导向新版本。

### 方式二：Ingress / Gateway 流量切换

通过 Ingress Controller（如 Nginx Ingress、Istio Gateway）或 Service Mesh 控制流量比例，实现更精细的切换。

## 蓝绿部署的优缺点



|                                                    | 缺点                                                         |
| :------------------------------------------------- | :----------------------------------------------------------- |
| ✅ **零停机发布**：切换瞬间完成，用户无感知         | ❌ **资源成本高**：需要双倍资源（两套完整环境）               |
| ✅ **即时回滚**：发现问题秒级切回旧版本             | ❌ **数据库兼容性**：新旧版本共用数据库时，schema 变更需兼容  |
| ✅ **预验证**：Green 环境可提前测试，确认无误再切换 | ❌ **状态同步**：有状态服务（Session、缓存）需额外处理        |
| ✅ **版本并行**：新旧版本完全隔离，互不干扰         | ❌ **切换瞬间风险**：如果 Green 有隐藏问题，100% 流量会同时暴露 |

------

## 与其他发布策略对比



| 策略                     | 特点                   | 适用场景                     |
| :----------------------- | :--------------------- | :--------------------------- |
| **蓝绿部署**             | 两套环境，瞬间全量切换 | 需要快速回滚、资源充足       |
| **滚动更新**（K8s 默认） | 逐步替换 Pod，自动进行 | 资源有限、可接受短暂混合状态 |
| **金丝雀发布**           | 小流量验证，逐步扩大   | 需要渐进式验证、风险敏感     |

------

## 一句话总结

> 蓝绿部署是用**双倍资源**换取**零停机 + 秒级回滚**的发布策略。在 K8s 中通过 **Service Label 切换**或 **Ingress 流量控制**即可实现，特别适合对稳定性要求极高、且能接受资源冗余的场景。
